# PRD «Линии» (Lanes) 5v5 — 04. Бэкенд

> Раздел серверной части. «Линии» — следующий режим CS Magic: он сразу онлайн и пишется в существующий авторитетный `CSMagic.MatchServer` + `CSMagic.Api` (репо `CSMagic.Server`). Правила и числа баланса — в `02-game-design.md`, клиент — `03-frontend.md`, цели и метрики — `01-product.md`.
> Стек — тот же, что у CS Magic: .NET, текстовый UDP-протокол, SQLite+EF в API. Новых технологий не вводим.
> Валюта матча — **Деньги** (как `StartMoney` / `Money` в 5v5). «Золото» в CS Magic — донатная мета-валюта (`PlayerEntity.Gold`), к матчу отношения не имеет.
> Числа из `02`, на которые опирается раздел:
> - HP героя 400, без пола хэдшота;
> - Fast и Staff — хитскан; снаряды Heavy 45 м/с и Roklet 55 м/с;
> - Волны каждые 30 c, до ~70 Крипов; Лес — 4 Лагеря по 3 нейтрала;
> - строения T1 8000 / T2 10000 / Ядро 14000; урон героя по строению засчитывается только с ≤ 35 м;
> - пассивный доход 6 Денег/с;
> - таймаут 20:00; сдача — с 8:00, 4 из 5;
> - покупка в Фонтане и пока мёртв; Возврат 6 c;
> - конфиг `ServerConfig/lanes5v5.json`.

### 0.1. Что берём из осады Throne Wars

Осада устроена так: 3 линии, 18 Башен, 2 трона; классы `ThroneWarsRules` / `ThroneTowerRules`, данные `ServerObjectives/Map_ThroneWarsObjective.json` (schema 2). Фронт строит «Линии» поверх клиента осады (`origin/cod/throne-wars-map`), поэтому на сервере идём тем же путём.

| Кусок осады | В «Линиях» |
|---|---|
| `ThroneZone` / `ThroneBuildingDefinition` + `Load`/`Validate` (жёсткая проверка схемы, id, числа зданий) | **Берём**, обобщаем в `ObjectiveMap` со схемой `L1`: + пути Линий, спавны Волн, Лагеря, Фонтаны. Неверный файл → режим не стартует |
| `Unlocked` — порядок сноса по линии, трон открыт после зачистки линии | **Берём**, правила открытия (T1 → T2 → Ядро, «Бэкдор-защита») — по `02` |
| `Damage` / `DamageWall`: здание — бокс `Building_<id>` в коллизии; оба пути (хитскан и снаряд), попав в такой бокс, наносят урон | **Берём как есть** — строениям не нужен свой рейкаст. Добавляем правило ≤ 35 м от стрелка и урон от Крипов |
| `CollisionMap` — своя копия коллизии на матч, снесённое здание → обломки 0,4 м | **Берём**; сетку боксов строим один раз на копию матча |
| `ThroneTowerRules.Tick` — LOS от дула, ближайший враг, кулдаун, счётчик `shot` | **Берём** LOS и дуло. Выбор цели переписываем: Крипы первыми, агро на героя, атакующего героя, нарастание урона (`02`) |
| Смерть от Башни выставляет `IsAlive/Deaths` напрямую, в обход общего пути смерти | **Не берём**: в «Линиях» любая смерть идёт через общий путь (награды, ассисты, лента, отчёт) |
| `StateSuffix` (`S2;…` в `match_state`), старт ровно 4v4, респаун через `GunGameRespawnAt`, +100 Денег всей стороне за Башню | **Не берём**: свои сообщения (§3), `LobbyStartRules`, свой Таймер респауна, награды из `02` |
| `tools/sync_throne_map.py`, `tools/throne_network_smoke.py`, тесты конфигурации и маршрутов | **Копируем** как `sync_lanes_map.py` и `lanes_network_smoke.py` |

Оговорка: код осады не закоммичен и сидит на старой базе — до лаг-компенсации, 5v5 и аудита; `Program.cs` там 6,4 тыс. строк. Его перенос на текущий `test` — отдельная работа (веха L0, вопрос 1).

## 1. Что сервер симулирует

Сервер авторитетен за всё, кроме патронов и анимаций (патроны во всех режимах считает клиент).

| Система | На сервере |
|---|---|
| Фазы | `Waiting → Warmup → Round → MatchOver` (имена — как у клиента `03`), от тика. Таймаут 20:00, после него тай-брейк по `02` |
| Герой | HP 400 + Предметы, смерть через общий путь, Таймер респауна по формуле `02`, появление в Фонтане (`ApplyServerSpawn`, `RespawnVersion++`) |
| Крипы | Волна каждые 30 c на каждой Линии; движение по пути Линии; цель; атака; смерть; добивание → Деньги |
| Строения | 12 Башен + 2 Ядра (T1 8000 / T2 10000 / Ядро 14000), порядок открытия, выбор цели, гарантированное попадание, обломки |
| Лес | 4 Лагеря × 3 нейтрала: агро на атаковавшего, поводок 12 м, полное лечение при сбросе, респаун Лагеря |
| Деньги | Пассив 6/с от тика; добивание; убийство; ассист (урон за 10 c до убийства, 50% награды делится); Башня; Лес; серия смертей; камбэк; смерть от NPC без героев — половина награды ближайшим врагам (всё по `02`) |
| Магазин | Покупка в Фонтане (и мёртвым), продажа 50%, оружие не продаётся, отмена 100% за ≤ 10 c без выхода из Фонтана, расходники |
| Возврат | Канал 6 c, отмена уроном / движением / вручную, телепорт делает сервер |
| Сдача | С 8:00, 4 из 5 голосов стороны |

### Навигация Крипов — по путям Линий из серверных данных карты

На сервере нет NavMesh, а коллизия — только боксы. Поэтому Крипы не ищут путь, а идут по размеченной ломаной.

- Данные — в `ServerObjectives/Map_LanesObjective.json` (schema `L1`). Экспорт из Unity — по образцу осады (`03`), формат и валидатор — бэк.
- В файле — для каждой Линии и стороны:
  - вейпоинты `{x,y,z}` и ширина коридора;
  - спавн Волны;
  - строения: id, сторона, линия, порядок, позиция, радиус атаки;
  - Фонтаны: центр, радиус, точки появления;
  - Лагеря: позиция, поводок.
- Отдельный `Nav.json` с графом проходимости для Крипов **не нужен**. Граф точек база/Лес понадобится только ботам (§4).
- Движение: Крип хранит индекс сегмента и смещение поперёк коридора (слот в строю, чтобы Волна не слипалась). Высота берётся из вейпоинтов, коллизий с боксами нет: путь размечен без препятствий. Между собой Крипы не толкаются, есть правило «стоп, если впереди свой, а цель в радиусе атаки».
- Цель ищется раз в 100 мс (каждый 5-й тик) в радиусе агро по сетке 8×8 м; приоритеты — `02`. Погоня ограничена поводком, после неё Крип возвращается на ближайшую точку своей Линии.
- Атака:
  - ближний бой — урон по кулдауну;
  - дальний Крип и Башня — самонаводящийся выстрел с задержкой полёта, без свипа по коллизии. Это дёшево и не требует сетевого объекта на снаряд.
- Тест-гейт загрузки: вейпоинты не внутри боксов, у каждой Линии оба направления, у каждой стороны 6 Башен и Ядро.

### Урон по юнитам (оба пути)

- Класс `LanesUnits`: Крипы и нейтралы в массивах структур без LINQ (чтобы не плодить мусор для GC). Умеет `TryRaycast` по капсулам, `ApplyDamage` и выдавать позы для истории.
- `ApplyServerHitscanDamage` и `ApplyServerProjectileHit` в режиме `Lanes` проверяют игроков, юниты и боксы `Building_*`; засчитывается ближайшее попадание. Правило «оба пути убийства в согласии» распространяется на юниты: Деньги, лента, отчёт.
- Свои не бьются — только через `ServerTeamRules.IsFriendlyFire`; нейтралы — сторона `N`.
- **Лаг-компенсация по Крипам:**
  - позы юнитов пишутся в историю рядом с позами игроков: ≈82 юнита × 128 кадров × ~24 Б ≈ 250 КБ на матч;
  - хитскан перематывает юниты на `unitsViewTicks` из выстрела (§3);
  - снаряды догоняются по текущим позициям, как сейчас с игроками.
- NPC убивает героя через общий путь смерти; источник — `u<id>` / `b<id>` (требование N8 из `02`).

## 2. Бюджет тика (20 мс; 10 игроков, ~70 Крипов, 12 нейтралов, 14 строений)

Оценки до замера, подтверждаются нагрузочным тестом (§9).

| Статья на матч за тик | Оценка | Чем держим |
|---|---|---|
| Существующее: теневое движение 10 игроков, снимок истории, снаряды по игрокам | ~0,1–0,2 мс | — |
| Движение 82 юнитов по ломаной | 0,01–0,02 мс | O(1) на юнит |
| Поиск целей (раз в 5 тиков) | 0,01–0,02 мс | Сетка 8×8 м |
| Атаки юнитов, 12 Башен (LOS раз в кулдаун), Ядра | ≤ 0,02 мс | Очередь «урон в тике N» |
| **Снаряды игроков** (≤ 20 в полёте × хитбоксы 10 игроков + ~10 юнитов рядом + стены) | ~0,1 мс **с сеткой боксов**; 0,3–0,5 мс **без сетки** на карте в 300–600 боксов | Сетка для `ServerCollisionMap` (ускорит и теневое движение) |
| Снимок поз юнитов в историю | 0,01–0,02 мс | Пул массивов вместо `Select(...)` |
| Деньги, респаун, Возврат, голосование | < 0,01 мс | — |
| **Итого тик** | **~0,25–0,4 мс** | |
| Разбор запросов: 10 клиентов × ~120 пакетов/с = 1200/с × 10–25 мкс | 12–30 мс в секунду ≈ 1,5–3% ядра | Строку записи юнита собираем раз в 100 мс, ответ — склейка из кэша |

**Цена снарядов на 45/55 м/с.**
- **CPU:** за тик снаряд проходит один отрезок 0,9/1,1 м, и проверка одна, сколько бы ни была скорость. Время жизни при дальности 45/50 м — ~1 c против 1,4–1,8 c на 25/35 м/с, значит одновременно в полёте на ~30–40% меньше снарядов. Ускорение по CPU **дешевле**, а не дороже.
- **Ограничение:** при шаге > 1 м свип обязан быть отрезком по капсуле (так и сделано), а не проверкой точки.
- **Трафик:** одно событие на выстрел (`shoot_events`), не поток позиций. От скорости трафик не зависит.

**Ёмкость:** ≈ 3–5% ядра на матч → теоретически ~20 матчей «Линий» на процесс. Планируем **10–15 (~100–150 CCU в режиме)**, пока `LoadTest` не покажет `TickLateMax` < 5 мс.

## 3. Протокол — принимаем контракт `03-frontend.md` §3

Канон CS Magic:
- текст; уровни через `:`, списки через `|`, поля через `,`; `InvariantCulture`;
- клиент опрашивает, на каждый запрос — ответ;
- новые поля только в конец.

Контракт клиента из `03` §3 **принимаем как канон** (имена, поля, частоты), кроме пунктов в §3.3. Для «Линий» он не ломает старых клиентов: в режим `Lanes` может войти только новый клиент, а общая часть `match_state` `p[0..10]` сохранена.

### 3.1. Сводка сообщений и что делает сервер

| Сообщение (из `03`) | Частота | Серверная сторона |
|---|---|---|
| `get_match_state` → хвост `p[11]="Lanes"`, `p[12]="L1"`, `money`, `ownedWeaponsMask`, `armor`, `respawnIn`, `inFountain`, `recallLeft`, `teleportVersion`, `items`, `consumables`, `maxHp`, `overtime` | 4 Гц | Строка из кэша на игрока, пересобирается при изменении. `teleportVersion` растёт после Возврата; позиция берётся по `spawnId`, как при респауне |
| `get_units_state` → `units_state:<snapshotId>:<serverTicks>:<part>/<parts>:U1;id,type,side,x,z,yaw,hp,state,targetId,atk|…` | 10 Гц | Отбор юнитов в радиусе 60 м от **серверной** позиции героя. Части по ≤ 1200 Б, каждая — отдельная UDP-датаграмма на тот же запрос. Записи — из кэша тика. `serverTicks` — серверное время кадра истории; его клиент вернёт в `unitsViewTicks` |
| `get_lanes_state` → 14 строений, 6 фронтов Волн, Лагеря | 4 Гц | Одна строка на матч, пересобирается при изменении |

Каждое новое сообщение проверяет сессию (`authenticatedGameSessions` + совпадение endpoint), `matchId`, членство игрока, точное число полей и `seq`.

### 3.2. `unitsViewTicks` — с условием

Правило `ProjectileCatchUpClock`: сервер не принимает от клиента собственное время клиента. Поэтому:
- `unitsViewTicks` обязан совпадать с `serverTicks` из одного из **выданных** этому игроку `units_state` и лежать в истории;
- возраст ≤ 250 мс (окно `ServerShotTimeValidator`), значение не из будущего;
- иначе перемотки Крипов нет: выстрел проверяется по текущим позициям и пишется в диагностику, как отклонённый `snapshot_a_missing`.

|---|---|---|---|

### 3.4. Трафик на клиента (оценка)

| Поток | Вниз |

| `players_state` 30 Гц × 1,5–2 КБ (существующий, > MTU) | **45–60 КБ/с** |
| `units_state` 10 Гц × 1–2 части ≤ 1,2 КБ | 12–24 КБ/с |
| `lanes_state` 4 Гц × ~0,6 КБ | ~2,5 КБ/с |
| `lanes_events` 10 Гц, `match_state` 4 Гц, `lanes_board` 1 Гц | ~2–3 КБ/с |
| `shoot_events` + `projectile_hit_events` | ~2–3 КБ/с |
| **Итого** | **~65–90 КБ/с (0,5–0,7 Мбит/с), ~80–100 МБ за 20 мин** |
| Вверх: ~120 пакетов/с (было ~90) | ~10 КБ/с |

Главная статья — существующий `players_state` (вопрос 4). «Линии» добавляют ~30–40%.

## 4. Матчмейкинг, переподключение, ливеры, боты

| Тема | Решение по умолчанию |
|---|---|
| Очередь | Существующая очередь матч-сервера, режим `Lanes`, старт при 10 (`LobbyStartRules`); на стенде — `CSMAGIC_LANES_MIN_PLAYERS` (≥ 2) |
| Подбор | Как в 5v5: по порядку, баланс сторон ±1, стороны `Paladin`/`Undead` (в протоколе `P/U`) |
| Party | Нет ни в одном режиме — «Позже» (`01`) |
| Обрыв | В `Lanes` игрока **не удаляем через 30 c**: слот держится до конца матча, флаг `Disconnected`. Через 10 c без пакетов герой переносится в Фонтан и стоит там без награды за убийство (`02`); Деньги и пассив сохраняются. Возврат: `check_active_match` → `game_join` → полное состояние (`match_state`, `lanes_state` целиком, Предметы) |
| Ливер | `Abandoned=true`, если суммарно не в сети > 5 мин или не вернулся до конца матча; награда — только за доигранный матч (`01`) |
| Вся сторона ушла | `EndMatchIfSideForfeited` → `Forfeit` |
| Штрафы | v1 — учёт `Abandoned`; кулдаун очереди — по `01`/`02` после первых данных (вопрос 6) |

**Боты — открытый вопрос; сейчас их нет нигде.** По `01` их нет до M4, триггер возврата к вопросу — доля неполных матчей ≥ 15% или поиск p90 > 150 c. Оценка, если делать:

| Что | Объём |
|---|---|
| `MatchPlayer` с `IsBot` без endpoint: пропускает проверки UDP-сессии, движение — серверное теневое, стрельба — через те же `ApplyServerHitscanDamage` / `TryCreateServerProjectile` с ошибкой прицела | 1–1,5 нед |
| Навигация: пути Линий + граф точек база/Лес (дописать в Objective) | 1 нед |
| Поведение: стоять на Линии, добивать, бить врага в LOS, отходить при низком HP, Возврат, покупка по `recOrder` из `shop` | 2–3 нед (ИИ Крипов частично переиспользуется) |
| Отчёт (бот не идёт в `Players` для API), `isBot` в `lanes_board`, тесты | 0,5–1 нед |
| **Итого** | **~4–6 нед** одного разработчика; CPU ~10 мкс/тик на бота |

## 6. Античит (покупки и Возврат — в первую очередь)

Доверие клиенту — ноль. Лимит пакетов на IP, 4 КБ на пакет, проверку сессии и `seq` не ослабляем.

| Угроза | Защита |
|---|---|
| Покупка вне Фонтана | Зона проверяется по **серверной** позиции (уже прошедшей бюджет скорости), а не по `inFountain` клиента. Мёртвый герой стоит в Фонтане — покупать можно (`02`) |
| Дюп повтором пакета | `buySeq` строго растёт (как в 5v5); у `sell`, `use_item`, `recall`, `ping` — свои счётчики |
| «Купил-отменил» и «купил-продал» в плюс | Отмена (100%) — только ≤ 10 c **и** без выхода из Фонтана **и** только последней покупки этого Предмета; сервер помнит время и цену покупки. Продажа — 50% от фактически уплаченного; оружие не продаётся; тест «продажа < покупки» на весь каталог |
| Отрицательные / переполненные Деньги | Одна функция начисления с `checked` и потолком; цены ≥ 0 проверяются при загрузке `lanes5v5.json` |
| Сборка Предмета (`need_component`, `unique_owned`) | Компоненты и уникальность проверяет сервер по каталогу; клиентский список слотов не принимается |
| Подмена статов | Урон, HP, броню, скорость применяет сервер; клиент только показывает |
| Предмет на скорость против проверки движения | Бюджет скорости (`ServerMovementRules`) берёт множитель этого игрока; общий порог не поднимаем |
| Возврат на ходу / под уроном | Таймер 6 c на сервере. Отмена по любому урону, по сдвигу принятой позиции > 0,3 м, по выстрелу; клиентский `recall:cancel` — тоже отмена. Телепорт делает только сервер (`teleportVersion++`). `player_state` со старой позиции после телепорта отбрасывается, как после возрождения (`AwaitingSpawnPosition`) |
| Возврат мёртвым / после конца матча | `not_alive`, фаза `Round` |
| Снос Башни с другого конца карты | Урон героя по строению — только с ≤ 35 м от **серверной** позиции стрелка до строения; дальше — 0 урона |
| Урон по своим строениям и Крипам | Только через `ServerTeamRules.IsFriendlyFire` |
| Скорострельность по юнитам | Те же `ServerShotTimeValidator` и `ServerWeaponSwitchFireGate` |
| Пинги-спам | Не чаще 1/с; координаты — в пределах карты |
| Maphack | В v1 все игроки видны всем (как в других режимах); юниты — по радиусу (вопрос 3) |

## 7. Эксплуатация

- **Выкатка** — как у матч-сервера сейчас (`csmagic-release-ops`); на общий сервер — только с подтверждения пользователя.
- **Файлы рядом с сервером:**
  - `ServerMaps/Map_LanesCollision.json`;
  - `ServerSpawns/Map_LanesSpawns.json`;
  - `ServerObjectives/Map_LanesObjective.json`;
  - `ServerConfig/lanes5v5.json` (тайминги, Деньги, каталог, NPC).
  
  Тест «файл в репо = значения по умолчанию», как у `classic5v5_tdm.json`.
- **Включение режима:** флаг окружения (например, `CSMAGIC_LANES_ENABLED`) — только когда сцена есть в сборке клиента. Урок `CSMAGIC_CLASSIC5V5_MAP`: обе стороны обязаны считать одни стены.
- **Телеметрия:** в `[TELEMETRY]` добавить `LanesMatches`, `Units`, `LanesTickMsMax`, байты ответов по типам.
- **Логи:** одна строка на событие (`LANES WAVE ->`, `LANES TOWER DOWN ->`, `LANES BUY ->`, `LANES RECALL ->`), без JWT.
- **Лимит на IP:** ~120 пакетов/с на клиента × 5 друзей за одним Wi-Fi или CGNAT оператора ≈ 600/с — выше лимита 500/с на IP. Проверить на закрытом тесте; если упрёмся — сначала снижаем частоты (`lanes_events` 5 Гц), а не ослабляем лимит.
- **Стоимость:** отдельного железа не нужно, 10–15 матчей помещаются в текущий процесс. Растёт трафик: ~0,6 Мбит/с на игрока → ~60 Мбит/с на 100 игроков в режиме. Проверить тариф канала на проде.

## 10. Открытые вопросы (решение по умолчанию — если никто не возразил)

1. **Порядок веток.** «Линии» опираются на 5v5 (PR #47) и на осаду Throne Wars (не закоммичена, старая база); PR #49 (аудит) тоже правит `Program.cs`. **По умолчанию:** влить #47 и #49 в `test` → перенести осаду отдельным PR (L0) → «Линии» веткой от `test`.
2. **Боты.** **По умолчанию:** нет до M4 (как в `01`); оценка — 4–6 нед, запуск по триггеру из `01` (неполные матчи ≥ 15% или поиск p90 > 150 c).
3. **Видимость врагов (maphack).** **По умолчанию:** v1 — все игроки в `players_state`, как в других режимах; фильтр по обзору стороны — если `02` введёт туман.
4. **Размер `players_state`** (~1,5–2 КБ при 30 Гц, > MTU, касается и 5v5). **По умолчанию:** замер на тестовом сервере до L2; если подтвердится — компактный `get_players_state_v2` для всех режимов отдельной задачей. «Линии» не блокирует.
5. **Потолок процесса и лимит на IP.** **По умолчанию:** один процесс держит 10–15 матчей «Линий»; при упоре в лимит 500/с на IP снижаем частоты опросов, а не лимит. Несколько процессов или портов — когда `TickLate` начнёт расти.
6. **Штрафы за ливы.** **По умолчанию:** v1 — `Abandoned` и награда только за доигранный матч; кулдаун очереди — после данных беты.
7. **Награда за длинный матч.** XP и серебро сейчас одинаковые за 3 и за 20 минут. **По умолчанию:** таблица без изменений на закрытом тесте; масштаб — решение `01`/`02` до открытого релиза.
8. **Рейтинг «Линий».** **По умолчанию:** без рейтинга; данные копятся в `MatchParticipation` с первого матча.
9. **Учебный матч «Одна Линия»** (`01` §6 «Онбординг»: локальная сцена или серверная комната на одного). **По умолчанию бэка:** серверная комната `LanesTutorial` (1 игрок, одна Линия, без отчёта в API) — ~1 нед, потому что Крипы и Башни уже есть только на сервере. Локальная сцена потребовала бы второй копии ИИ на клиенте.
